initiate: bootstrap one repository

1. Run

Use the standalone clankos-bootstrap skill's scripts/bootstrap, or bin/initiate
from a ClankOS checkout:

    scripts/bootstrap --image vX.Y.Z

Run at the Git repository root with Git, Bash and Docker available. The version
must be a published fixed release. No host software is installed. Without
--image, an existing garden's configured fixed release is used. A new garden
must select a release; there is no fallback to latest.

2. Writes

The launcher verifies the runtime and companion skills image before any garden
writes. Both must name the same release, source commit and apply-v1 protocol.
It writes a new .clanka/config.yml with the selected image, projects directory,
archive policy and exclusions; an intray with a file ID; _*/ in .gitignore;
and a marked ClankOS block in AGENTS.md. An explicit --image updates the root
image setting, including in an existing garden. Other configuration and content
outside that block are preserved. Git's managed archive exclusions are updated
from the saved configuration, including local child scopes.

It then runs explicit apply-v1 at the root. Method zero comes from the runtime's
source commit. Optional methods are installed only when the configuration
selects them. Ownership is recorded beside the configuration; skills and their
lock are committed material. No auto/bin, command links or approval rules are
created. Existing legacy wrappers are left for the user to inspect and remove.
A fresh clone runs its committed skill bundles directly.

3. Options

--archive uncommitted|committed|remote selects archive storage for a new garden.
Uncommitted is the default; remote requires --keeper URL. --ask asks about the
archive and then the responsibility tree; --no-tree skips that tree dialogue.
--project creates a leaf configuration with no projects directory or tree.
Existing configuration takes precedence over these options.

4. Completion and retry

Nothing is staged, committed or pushed. Review configuration, ownership, skills
and skills-lock.json together. Separate repositories are not applied. If apply
fails, configuration and saved ownership remain for retry. Run the bundled
clankos apply-v1 after correcting the reported problem.

Exit 0 means complete. Usage and root errors exit 2. Pair checks exit 1 when
refused; Docker and apply failures retain their exit status. Missing host
commands exit 127.
