pos-refile: moving tasks to where they belong

bin/pos-refile runs this protocol in the ClankOS container. The
commands are poslib's, at the commit the image was built with:
https://github.com/ClankaOperatingSystem/poslib


1. Where tasks are kept

The working directory is the root. The files where tasks are kept are
the corpus poslib's doc/pos-directory.txt describes: every Org file
under the root but those in the directories the configuration
excludes. intray.org, in the root, holds the tasks not yet placed,
under "Unsorted". The root's pos-config.el, if it has one, sets:

    pos-refile-rules   pairs of a pattern and a file relative to the
                       root: a heading the pattern matches is suggested
                       for that file

A task in a directory the corpus does not read, an attic or an
archive, is left there on purpose and is not looked for. The open
tasks of a document that is about to be sealed are brought into the
intray by "archive-integrity salvage" ("clankos-run help
archive-integrity").


2. Out of the intray: plan, review, apply

  - Plan. "plan [FILE]" writes FILE, an Org file with one table row
    for each entry of the intray, and each entry quoted in full below
    the table:

        | act  | line | heading          | file          | under | excerpt |
        | move |    4 | Send the invoice | work/todo.org |       |         |
        | ?    |    5 | Buy milk         |               |       |         |

    A row whose heading a rule matches is suggested as "move" to the
    rule's file. The rest are "?". Nothing is moved.
  - Review. A person or an agent edits the table. To move an entry:
    act "move", file the target relative to the root, and optionally
    under, the path of the heading it goes beneath. To leave it: "skip"
    or "?".
  - Apply. "apply [FILE]" moves each "move" entry, with its subtree, to
    its target: beneath the heading named, or at the end of the file.
    "apply --dry-run" reports what it would do.

The report counts the entries moved, left, with a missing target, with
a target the root may not write, and no longer at their line. An
entry whose target file or heading does not exist is not moved; nor
is one whose target is another repository's, or a file the corpus
does not read. An entry is found by its line and heading as the
plan recorded them: if the intray has changed since, it is not moved,
and a new plan is needed.

FILE is refile.org in the root unless given.


3. In the container

bin/pos-refile gives its arguments to bin/clankos-run. The files are
the host's, at their own paths, and are written as the invoking user.
pos-config.el is Lisp, and is run in the container.

The report is on stdout. Emacs's own messages are on stderr.


4. Exit status

    0     done
    2     usage, or no intray.org in the working directory
    255   an Emacs error; the message is on stderr
    125   Docker failed to run the container
    126   the workspace is not visible in the container
    127   docker, or the command in the image, was not found
